# `MZ64` image contract, version 1

Status: normative for target `x86_64-pc-dos64`; header size 48 bytes.

An `MZ64` file is selected by the first four little-endian bytes
`4d 5a 36 34` (`MZ64`). It supports the same memory model and entry ABI as a
raw `.COM` but carries a memory size and load-time image-relative relocations.

## Header

| Offset | Size | Field |
|---:|---:|---|
| 0 | 4 | magic `MZ64` |
| 4 | 4 | header size, exactly 48 |
| 8 | 8 | file payload size |
| 16 | 4 | entry offset, less than payload size |
| 20 | 4 | requested stack size in bytes; zero selects the target minimum |
| 24 | 4 | relocation count |
| 28 | 4 | relocation-table file offset, normally `48 + payload_size` |
| 32 | 8 | memory size, at least payload size and at most 16 MiB |
| 40 | 8 | reserved zero |

The file must contain the full header, payload, and `relocation_count` records
of 16 bytes each. The table begins at the recorded offset, does not overlap
the header or payload, and ends exactly at file end. Header and table reserved
fields are zero. Arithmetic is checked before addition or multiplication.

## Payload and BSS

The payload is copied to `load_address` (`PSP + 0x2a0`). Bytes from
`load_address + payload_size` through `load_address + memory_size - 1` are
zero. Entry is `load_address + entry_offset`. Section alignment and writable
versus executable permissions are enforced by the producer; the version 1
loader has one RWX process range. The loader reserves a 64 KiB application
stack immediately below the process allocation and enters the image with its
16-byte-aligned top; the image must not assume a larger stack.

## Relative relocations

Each table entry is:

| Offset | Size | Field |
|---:|---:|---|
| 0 | 8 | destination offset from `load_address` |
| 8 | 8 | signed base-zero addend |

For every entry the loader performs one checked operation:

```text
memory[load_address + destination] = load_address + addend
```

The destination slot and represented value must both be eight-byte aligned.
The range must lie wholly inside initialized payload plus BSS. A load or
entry address outside the noncanonical target range is rejected. Entries may
overlap; the specified order is used once per entry. A header with no
relocations remains valid.

## Failure and compatibility

Bad magic falls back to raw `.COM` interpretation only when the file has fewer
than 48 bytes or does not claim the exact current header. A file beginning with
`MZ64` but violating any current-header rule is rejected, never reinterpreted.
Version 1 does not reserve alternate-version dispatch. Future headers must use
a different magic and a separately documented loader contract.
