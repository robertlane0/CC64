# CC64 provenance ledger

Last reviewed: 2026-09-24.

CC64 implementation code is authored for this repository from written contracts
and language/processor specifications. No implementation source, generated
table, machine-code fragment, test corpus, or build artifact from another
compiler is copied, translated, decompiled, or mechanically adapted.

## Permitted references

| Input | Use | Boundary |
|---|---|---|
| ISO/IEC 9899 C17 | token, declaration, expression, and statement semantics | behavioral requirements only; no implementation text |
| Intel SDM and AMD64 Architecture manuals | instruction encoding, flags, ABI-independent machine behavior | no copied code or generated encoding tables |
| System V AMD64 ABI specification | integer register assignment and stack alignment | specification only |
| `MS-DOS64/docs/*.md` observable contracts | PSP size, `INT 21h` interface, loader behavior, and emulator commands | interface facts only; no target source imported |
| Project-authored tests in `tests/` | expected CC64 behavior | original fixtures and assertions |

The nested `MS-DOS64/` directory is ignored and is neither a dependency nor a
source input to the normal CC64 build.

## Target changes on the edit branch

AGENTS.md section 1 permits a change in the `MS-DOS64` repository only on a
branch named `edit`, only to make the compiler operational, and only when it is
recorded here. `main` and the pinned revision stay unmodified so any build can
still be compared against the reference target.

| Edit revision | Reason and observed defect | Observable effect |
|---|---|---|
| `8b989fb` (branch `edit`, file `src/kernel/shell64.asm`) | CC64's startup contract requires a program to receive the text the shell was given after the program name, because `argc` and `argv` are built from it. A program started as `NAME ARG ARG` received an empty tail, and `argc` was always zero. The shell's program-execution path held the tail pointer in `R9` across the two calls that stage the image; the allocator uses `R9` as a scratch register, so the pointer handed to the spawn call was whatever the allocator left behind, and the child recorded a length measured from unrelated kernel memory. CC64 reproduced the defect with an original test (`C64H`, a program that prints its own argument vector) and located it by reading the length byte the target actually wrote. The change moves the tail pointer into a callee-saved register and restores it on every exit; it is minimal, carries nothing from CC64 into the target, and no target code was moved into CC64. | Before: `C64H` under the pinned revision receives `argc=0` and an empty first argument. After: it receives the tail arguments, and every image that parses arguments works. The pinned revision remains in the repository and is what the unmodified-target comparison uses. |
| `f36e84c` (branch `edit`, file `src/kernel/shell64.asm`) | The startup contract requires `argv[0]` to be the program's own name, and CC64's driver needs it because a driver reads its options from `argv[1]` onward. A program had no way to learn its name: the loader zeroes both file control blocks in the process prefix, and the command tail deliberately excludes the name. CC64 wrote the requirement into `docs/specs/abi-v1.md` first, then found the shell already holds the parsed name in `sh_fcb` in order to find the file, so the spawn path copies that name into the child's first control block in the DOS layout with the drive byte first. The helper is placed after the shell body so the shell's own code layout does not shift. | Before: a program started as `NAME ARG ARG` sees no name, and CC64's own driver on the target reads `argv[0]` as the program name, so it treats its first option as a source file and reports a lexer error inside the object. After: `argv[0]` is the name and the tail arguments follow it, the driver runs, and `C64H` observes `a0=C64H a1=AA a2=BB`. On the pinned revision the name field stays empty, so the startup passes `argc == 0` and the case fails visibly instead of silently. |

## Design decisions

| ID | Decision | Independent rationale |
|---|---|---|
| D-001 | Flat target and 16-byte stack, no red zone | target shares stacks with faults; deterministic interrupt-safe frame |
| D-002 | Project-owned `CC64O` tables and relocations | permits strict validation and deterministic target-only linking |
| D-003 | Stack-slot temporaries at `-O0` | simple frame invariants precede optimization |
| D-004 | `MZ64` uses explicit image-relative fixups | raw images cannot represent load-biased data addresses |
| D-005 | `int32_t` is the first target `int`/pointer-sized ABI | written target contract; avoids inheriting host LP64 |
| D-006 | Typed linear IR before machine selection | backend never consumes parser nodes |
| D-007 | Limits reject ambiguous or unbounded translation | deterministic failure for hostile input |
| D-008 | Preprocessing uses explicit hidesets and bounded expansion depth | prevents recursive macro runaway while retaining blue-painted tokens |
| D-009 | Failed preprocessing never publishes its temporary output | diagnostics cannot be mistaken for a successful translation |
| D-010 | Typed AST nodes carry explicit C types and source locations | later lowering cannot depend on parser token layout |
| D-011 | `-O0` uses balanced stack temporaries and explicit frame slots | makes ABI and call behavior inspectable before optimization |
| D-012 | Linker emits a target-owned entry/exit trampoline for raw COM | keeps startup independent of host CRT while preserving `main`'s return byte |
| D-013 | Target service functions are emitted by the CC64 encoder only when referenced | keeps the freestanding boundary in project-owned machine selection and avoids importing a target runtime |
| D-014 | `MZ64` data fixups use image-relative destinations and addends | the target loader supplies the load bias, so the same payload remains position-independent |
| D-015 | The startup stub exposes a bounded one-argument argv view from the target PSP | this is the minimum target interface needed by the first hosted compatibility gate; richer tokenization is recorded for the next ABI revision |
| D-016 | A separate stage1 smoke program gates target bootstrap execution | isolates loader, relocation, startup, and backend evidence from the larger self-hosting claim |
| D-017 | MZ64 relocation tables retain only image-relative data fixups | absolute/load-biased values are rejected instead of being silently made non-portable |
| D-018 | Release fuzzing uses a fixed PRNG seed and temporary inputs | malformed-input smoke remains reproducible without checked-in adversarial artifacts |
| D-019 | Reproducibility compares a content manifest of two path-independent clean exports, including compiler-produced target artifacts | detects nondeterministic object, archive, dependency, executable, or target-image output rather than checking one file only |
| D-020 | Target integration pins the adjacent MS-DOS64 revision and checks volume state before/after execution | prevents a passing local image from being attributed to an unpinned or modified loader or a dirty volume |
| D-021 | `src/runtime` is excluded from the host bootstrap object list | target runtime definitions are emitted for target builds rather than linked into the host driver |
| D-022 | A tagged aggregate definition completes the existing local tag object | preserves C typedef/forward-declaration identity for self-hosting and ordinary C clients |
| D-023 | `void *` compares compatibly with an object pointer | implements the C null/general-pointer comparison rule without inheriting host ABI behavior |
| D-024 | Image inspection rejects empty/oversized raw payloads and negative or out-of-range MZ64 fixups | keeps independent validation aligned with the pinned image contract and makes malformed-input tests meaningful |
| D-025 | Target service thunks preserve path and exit arguments in their target registers | keeps the encoder-owned runtime boundary faithful to the documented DOS register contract |
| D-026 | Strict release mode requires a clean source tree and non-skipped emulator evidence | prevents a local aggregate from certifying an unclean or incomplete release |
| D-027 | Independent object readers and the linker reject overlapping ranges, uncovered bytes, undersized executable alignment, and out-of-range symbol sizes | enforces the version-1 table layout before relocations or output are trusted |
| D-028 | Backend symbol ordering compares every serialized tie-breaker field | prevents nondeterministic ordering of otherwise equal-prefix symbol records |
| D-029 | Repeated encoder-emitted target service definitions are coalesced by the linker | permits multiple translation units to reference the same project-owned thunk without duplicate-symbol failures |
| D-030 | Bochs validation uses the pinned target bochsrc template, a term display, and a dedicated serial PTY | exercises the target's real serial-input shell path without importing emulator or OS implementation code |
| D-031 | Target compilation uses a dedicated standard-header shadow directory | keeps target translation units free of accidental host libc headers while preserving the compiler's source spellings |
| D-032 | Production translation units are probed individually with the target header profile before linking | makes self-host coverage and the first failing construct explicit and deterministic |
| D-033 | Relocations are applied to the flattened image payload, after per-kind section buffers are merged at their final offsets | the per-kind buffers are scratch; writing a final-layout offset into them corrupts unrelated memory, and BSS is zero-filled by the image buffer rather than copied |
| D-034 | Every non-BSS data object is aligned to at least eight bytes | keeps the pinned MZ64 contract that a relocated pointer's represented value is eight-byte aligned, so the loader needs one aligned store per fixup |
| D-035 | One declarator per AST node, chained through `next`, spliced whole into statement lists | a single node per declaration statement silently dropped later declarators, which then lost their frame slot and were emitted as external references |
| D-036 | Output files are created once and written once from a fully built in-memory image; there is no temporary-file rename step | the pinned target dispatches no `rename` (56h) or `delete` (41h) service, so the temporary protocol could never run on target; a truncated write stays detectable through the CC64O and MZ64 checksums |
| D-037 | `cc64_create` and `cc64_lseek` join the emitted service thunks, using the target's RAX result and CF error convention | the compiler must open and seek real files, and both services are already listed in the pinned ABI table; the file-descriptor result register is read back from the target source rather than assumed from classic DOS |
| D-038 | A variadic function spills the six integer argument registers into a save area in its own frame, and `va_arg` steps eight bytes per slot | an eight-byte slot stride is required to read whole registers and to keep the walk independent of the argument type; a `sizeof`-based stride silently misreads every `int` variadic argument |
| D-039 | Only the end of a whole preprocessing run emits an end-of-file token | the lexer ends every source, so copying an included file's end token into the output truncated `-E` and `--dump-tokens` at the first include |
| D-040 | Array bounds, enumerators, and case labels are evaluated by a project integer constant-expression evaluator | accepting only a bare literal rejected ordinary spellings such as `[4 * 2 + 1]`, a macro, or `sizeof`, including in CC64's own sources |
| D-041 | Floating constants are converted by project code with a 128-bit intermediate and round-to-nearest-even | a bootstrap build and a self-hosted build must emit identical objects, so the conversion cannot depend on whichever library each build links; values outside the documented range are diagnosed rather than misrounded |
| D-042 | An array or function member decays to its address, like a bare identifier of that type | loading a member of array type produced the first element's value instead of the member address |
| D-043 | The target startup routine is emitted into every image that defines `main`, and the link trampoline calls it | the old trampoline passed a pointer to the process prefix where `argv[0]` belonged, so no target program could read its own name or arguments; a required startup symbol makes the entry path part of the object contract |
| D-044 | The startup copies the command tail into its own frame, terminates it, and splits it in place on spaces and tabs; the length field is read as a byte | the prefix stores a one-byte length, so reading a quadword would copy unrelated prefix bytes; scanning to the terminating NUL removes any bound on the tokenizer loop |
| D-045 | Every hand-encoded startup instruction is checked against the assembler byte for byte | four separate encodings in the first draft were wrong or invalid (`C7 /1`, a reversed 8-bit move, a spurious REX bit), and an invalid opcode silently hung the target |
| D-046 | Section alignment padding is applied to the output buffer before the section payload is appended | the previous order appended the padding after the offset had already been aligned, doubling every gap and leaving sections at unaligned offsets that broke eight-byte data relocations |
| D-047 | The startup copies the command tail with an explicit byte loop instead of a repeated-string move | the startup runs before any library code can establish the direction flag, so a repeated move would depend on state the image itself has not set; the loop also gives the copy a bound the instruction does not |
| D-048 | A relational operator selects the condition code for the operand order the comparison actually computes, and signedness selects between the signed and unsigned condition | the table mixed operand orders, so unsigned `>` behaved as `>=` and unsigned `>=` behaved as `!=`; a loop guarded by an unsigned `>` then never terminated, which is why the target formatter hung while the host build passed |
| D-049 | Both operands of the conditional operator are converted before its result type is chosen, so an array or function operand becomes a pointer first | C17 converts the operands; without the conversion a conditional over two string literals, or over a string literal and a pointer, was rejected as having incompatible branches, which is ordinary C that the compiler's own sources use |
| D-050 | Array suffixes on a declarator are collected in source order and applied in reverse, so `a[2][3]` is two arrays of three | applying them as they are read builds the opposite shape, which still compiles and then misplaces every initializer and reports the wrong `sizeof` |
| D-051 | The startup copies the eight name bytes of the control block ahead of the tail copy and separates them with one space, so one tokenizer pass yields the name and the arguments | the control block stores the name space padded, so a fixed-width copy would either run the extension into the first argument or stop at a terminator before the tail; reusing the existing splitter keeps one rule for both |
| D-052 | A service thunk returns the target's result value on success and -1 on failure, decided by the carry flag the interrupt return restores | the target reports a refusal by setting CF and leaving a small positive code in RAX, and that code reads as a valid result: error 6 from a file read is a plausible handle, error 25 from a seek is a plausible offset, and the max-free count from a refused allocation is a plausible address; the runtime library was already written against a negative failure, so the thunks now provide it |
| D-053 | The variadic save area holds the six argument registers followed by eight copied slots of the caller's stack area, and the argument walk continues across the boundary unchanged | the walk in `va_arg` is a flat eight-byte step, so arguments the caller had to pass on the stack were never reachable; copying a fixed number of slots keeps the walk flat, and slots the caller did not fill are never read because a caller only reads the arguments it passed |
| D-054 | The overflow copy in a variadic prologue is unrolled rather than looped | a loop needs encoder-internal label ids, and those share one label space with the per-function ids the lowering hands out, so a fixed id can silently merge with a branch label in a large function |
| D-055 | `fclose` releases any handle the stream owns, not only a writable one | the target keeps thirteen handles for a whole process, so an unreleased read handle is still holding a slot; a program that opened several files in sequence ran out of handles and every later create failed |
| D-056 | A current directory contributes no prefix to a joined include candidate, so the candidate is the bare name | the target's name parser is DOS-strict and refuses any name containing a separator, so a `./name` candidate could never be opened there while a host accepts both spellings as the same file |
| D-057 | `fread` and `fwrite` satisfy a request in as many service calls as it needs, each at most 0xFFFF bytes | the target's read and write services carry the byte count in a sixteen-bit register field, so one call cannot move a source-sized file; a single call silently moved a short prefix and the caller saw a truncated transfer |
| D-058 | The target's integer conversion saturates at the ceiling of the type it is converting to: the unsigned maximum for an unsigned conversion, one past the signed maximum for the magnitude of a signed one | clamping an unsigned conversion at the signed maximum reports overflow for 18446744073709551615, so `SIZE_MAX` and every constant above the signed maximum were rejected by the front end that runs on the target, while a host library accepted them |
| D-059 | The startup keeps the argument vector and the command text in separate frame regions, the vector below the text with a slot to spare, and the argument count is bounded at sixteen | the vector grew upwards from its base into the name and tail copy, so a command with more than ten arguments overwrote the first tokens with vector entries: the program saw a corrupt name, empty arguments, and a wrong count |
| D-060 | A declaration is parsed, lowered, and then released from the node arena, and only the values the back end still needs are copied into the durable arena: an object's initializer, a static object's initializer, and a string literal | the front end otherwise holds every function's syntax tree at once, and the largest unit in the project needed about twelve megabytes, which is twice the target's whole heap; the release keeps the peak near four and a half megabytes while the durable arena still holds names, types, literal text, and the lowered program |
| D-061 | The lowerer numbers string literals for the whole program rather than per declaration | a per-declaration counter restarts at zero, so two literals get the same symbol name, and the object writer's string table then merges two different literals into one name |
| D-062 | A repeated string-table entry takes the offset of the earlier entry as the sum of the lengths of all entries before it, each counting its terminator | the sum started at one, which counts the empty first entry twice and yields an offset one byte into a name, so every symbol after a repeated name pointed into the middle of another name |
| D-063 | A token's positions and offsets are 32-bit, and a source past that bound is diagnosed rather than truncated | the token record is the front end's largest per-word structure and a large unit holds tens of thousands of them; a truncated position would silently misplace a later diagnostic |
| D-064 | The lexer builds each token's text in one reused buffer and copies the finished text into the arena | a token that owned a heap block cost the target one block header per token, which for the largest unit was over a megabyte of pure per-block overhead |
| D-065 | No interface takes or returns a structure by value; a mark is passed by address | version 1 has no aggregate calling convention, so a by-value structure parameter is a construct the compiler cannot lower, and the compiler's own sources are the first program that has to compile them |
| D-066 | The parser compacts the preprocessed token stream in place and releases it from the front as it is consumed | a second array of every token costs more than the tokens themselves for a large unit, and holding the whole stream while the lowered program grows adds its full size to the peak |
| D-067 | A lowered instruction keeps its counters, labels, and case count in 32-bit words, packs its two flags into one word, and holds the immediate and the floating value as alternatives | the instruction record is the largest structure the lowerer produces and a large unit lowers to tens of thousands of them, so the record's size sets the peak directly |
| D-068 | A growing token list adds a fixed number of entries once it is large, and a source's list is sized from the source length up front | a doubling step has to hold the old and the new array at once, and for a large unit that is megabytes of contiguous space the target's first-fit heap cannot always provide in one piece |
| D-069 | The lexer produces newline tokens only when the caller keeps them | a caller that drops them afterwards held about a third more tokens than it used, and a source-sized list is the largest single allocation in a compile |
| D-070 | The parser compacts the preprocessed token stream in place instead of copying it | a second array of every token costs more than the tokens themselves, and the parser owns the array afterwards |
| D-071 | The startup accepts up to thirty-two arguments, and the argument vector has room for them plus the terminator | linking every object of a self-hosted build needs more than sixteen arguments, and the vector ran into the command text |
| D-072 | The self-host stage stages sources and objects under short names and links the runtime library objects with the compiler's own linker | a command tail is bounded to 143 bytes on the target, so a link of twenty objects only fits with four-character names, and the self-hosted link needs the runtime objects the bootstrap link uses |
| D-073 | A function is encoded as soon as it is lowered, and its lowered form is released with its syntax tree | the whole unit's lowered program was the largest thing a large unit had to hold: the largest unit's durable arena fell from 2.08 MiB to 1.25 MiB, and the encoder's symbol records are filled in as each function is encoded so the object's bytes do not depend on the order the encoder met them |
| D-074 | Instructions, labels, cases, and a function's record are built in a second arena that the driver releases per declaration | names, types, symbols, and the durable copy of a literal's text are still in the arena that lasts the compile, so nothing the back end needs outlives its declaration |
| D-075 | The preprocessed token list is sized once from the translation unit's main source, and the parser hands back the array the compaction dropped | a per-source reservation accumulates: a unit with twenty includes reserved several times the tokens it produces, and the target refused the request even though the total free space was larger |
| D-076 | Basic types and pointers to basic types are shared for one arena, checked against the arena's own number | a type record is never changed once built, except a structure or union placeholder that the parser fills in when its members are known, so sharing is indistinguishable from copying; a unit of ten thousand tokens used to build about as many type records as it had expressions. The arena's number distinguishes a new arena from a released one built at the same address |
| D-077 | `remove()` builds the file control block the target's delete service reads | the runtime's `remove()` was a stub reporting failure while the target has dispatched a delete service; the block's name and extension fields are blank-padded because the service compares the block with the directory entry byte for byte |
| D-078 | The linker takes `--free`, which unlinks each object once it has been read, and it is off by default | an object is read once and never read again, so releasing it as it is consumed changes nothing about the link; the volume's data area is smaller than the image, the objects, and the image together. The option is named for what it does to the volume's free space rather than for its length, because a target command line is a fixed, short buffer |
| D-080 | Every deferred C17 construct has its own diagnostic identifier instead of falling through to a generic parse failure | the lexer already classified `_Generic`, `_Complex`, `_Imaginary`, `_Thread_local`, and `_Alignof` as keywords, so the parser met them with "expected primary expression" and then a cascade of follow-on errors; a program that used a deferred construct could not tell which one was out of contract, and the subset document promises a stable diagnostic for each. `long double` is the one that had to be rejected rather than diagnosed later: the ABI gives binary64 to `double`, so accepting the spelling silently gave the program a narrower type than it asked for |
| D-081 | A target conformance case is named by a unique four-character DOS 8.3 stem | two cases shared the stem `C64I`, so the second overwrote the first case's image, object, and volume on disk, and the run's evidence for that stem was ambiguous even though both cases happened to pass |
| D-082 | `NODE_NULL_STATEMENT` lowers to nothing | a static assertion inside a function body produces a null statement, and the lowerer's default case sent it to expression lowering, which reported "expression node cannot be lowered" for a declaration that is already checked |
| D-083 | The formatted-output sink counts a character whether the destination is a bounded buffer or a stream, and a 64-bit conversion reads the whole variadic slot | the stream branch returned without advancing the count, so `printf`, `fprintf`, and `vfprintf` reported zero however much they wrote. A single `l` was recorded as a distinct size that no fetch tested, so `%ld` read an `int` and printed the wrong number for any argument outside 32 bits; a variadic walk in this ABI moves one whole eight-byte slot per argument, so the no-modifier case reads the low half and every sized case reads the whole slot |
| D-084 | The target header declares only what the target library defines | `strdup`, `strtof`, and `strtod` were declared but never defined, so a program that called one failed at link with an unresolved symbol instead of at compile with a clear diagnostic. `strdup` is implemented; the two floating conversions are removed, because the version 1 contract defers floating conversion and a second, independently written decimal converter that no test exercises would be worse than a documented absence. `vfprintf` and `vsnprintf` are declared with the real `va_list` type instead of a placeholder `void *` |
| D-085 | The image inspector applies a load bias to an image and checks every fixup, and the fuzz gate runs it at five biases and at two that must be refused | an `MZ64` payload is position independent by design, so the property is only evidence if the fixups are walked at more than the one bias the loader happens to use; a fixup that left the loaded image at some bias is a defect the format alone does not rule out. Every field the loader reads is bounded, so each one is mutated and required to be rejected before it is acted on rather than after |
| D-086 | A `f`-suffixed constant is rounded to binary32 by project code and then widened back to the binary64 the instruction carries | the four binary32 bytes were copied straight into the eight-byte value, leaving the high half zero, so every float constant in every program was a denormal close to zero. A float compare then reported its operands equal whatever they were, and because the test corpus had no floating case at all, nothing noticed. The widening is project code for the same reason the rounding is: a host conversion is not available on the target and would not round the same way in a self-hosted build |
| D-087 | Multiplication and division accept the floating types; the remainder and the bitwise operators stay integer-only | both were grouped with the integer-only operators, so `a * b` and `a / b` on a float were rejected with "integer operator requires integer operands" while `a + b` and `a - b` worked. The grouping followed the operators' own definitions, so the split is the correction and the message names the rule it applies |
| D-088 | The Bochs gate runs a named subset of the conformance corpus rather than cases of its own | the milestone's exit criterion is that the corpus runs on both emulators, and two ad-hoc cases did not meet it. The subset is named so a case that is renamed or dropped is a failure rather than a silently smaller run, and it is chosen for what a second emulator has to agree about rather than for volume, because it is far slower than the other one |
| D-089 | A diagnostic marks the declaration being parsed wrong and the parse continues; `failed` is reserved for a stream that cannot be parsed further, and the unit's verdict comes from the diagnostics the sink holds | every diagnostic set the parse-failed flag, so a program with three independent errors reported one and a user had to fix and recompile three times. A missing token is recoverable because the caller skips to the next terminator; an exhausted stream is not. The per-declaration flag is cleared before each declaration, and the whole unit's verdict is read from the sink so clearing it cannot lose an earlier declaration's diagnostic |
| D-090 | The license inventory is a table in the policy document and the audit requires every tracked file to be covered by a row | a policy that says the project's own code is under the repository license is not an inventory, and nothing checked that a newly added file had a license decision at all |
| D-091 | A performance gate measures the clean build twice, each production unit, and both image forms, and fails when a measurement is outside a budget the contract states | the release required performance measurements and the repository had none: every timer in it was a test deadline. Two builds are timed so a difference is reported as an unstable measurement rather than smoothed away, and a build that varies that much is not something a target gate should depend on |
| D-092 | The machine-code decoder is project-owned, recognises the forms the encoder emits, and reports an unrecognised byte as unknown rather than guessing | a test that checks a prologue, a call, or a service boundary needs instructions, not a hex string, and the alternative would have been to read another tool's output, which the backend and object gates forbid. The decoder resynchronises one byte at a time after an unknown so the rest of the section still decodes, and an unknown is a visible result rather than a silent misreading |
| D-093 | One place decides whether a missing emulator is a skip or a failure, and the release gate always asks for a failure | six harnesses each repeated the same skip-or-fail test, and the aggregate gate exported the strict variable only in its strict form, so an ordinary `make check-release` on a machine with no emulator recorded that a target property had been checked when nothing had booted. The rule is now stated once and the release gate cannot certify a run with no target evidence |
| D-094 | A redeclaration is a conflict within one scope; a name in an enclosing scope is shadowed, and only an initialized file-scope definition conflicts with another | the duplicate check used the lookup that reaches parent scopes, so ordinary shadowing, which every C program does, was rejected as a redeclaration. Separately, a file-scope object with an initializer was not counted as a definition at all, so two initialized definitions of one name were both accepted and the second silently overwrote the first. A tentative definition, which C allows a unit to repeat, is recorded separately from an initialized one so `int a; int a;` stays valid while `int a = 1; int a = 2;` does not |
| D-095 | The image compatibility gate checks the fields the pinned contract states and requires a version this compiler does not write to be refused | the ABI document promises that a later version preserves version 1 images or says why it cannot, and nothing checked the promise. The gate reads the contract's own numbers rather than restating them, so a change to a contract is a change to the document first. A payload length is not required to be a multiple of the entry alignment: the contract pins the address the payload is loaded at, not its size, so the check is that every bias the loader may use is entry aligned |
| D-079 | `static_assert` and `_Static_assert` are evaluated while the unit is parsed and emit no code; `__func__` is a per-function `static const char` array bound under the name the body spells and renamed afterwards; `_Alignof(type)` reuses the `sizeof` result node | the assertion needs no representation in the IR, so it is checked in the parser, and a case that only compiled would not notice a wrong evaluation. `__func__` needs one object per function, so the symbol is renamed to a private per-function name after the binding is made, and a scope binding now keeps its own copy of the name because a binding that aliased the symbol's name stopped matching once the symbol was renamed. `_Alignof` differs from `sizeof` only in that it takes a type name, so it produces the same constant node |

| D-096 | An initializer written with braces is a list and an initializer written as one expression is a single value, and the node records which | both shapes arrive as the same node, so an aggregate initialized from a call was walked as a member list: the call was matched against the first member, the remaining members kept whatever the zeroing pass left, and the result was silently wrong. The distinction is recorded at parse time because a later phase cannot recover it from the shape |
| D-097 | A qualified copy of a record is the record itself, so record identity is read through a pointer back to the type the copy came from | two declarations of a pointer to `typedef struct { ... } S` each built a qualified copy, and two copies compared as two unrelated records because a copy is a distinct address. Every program that typedefs a record and passes a pointer to it was rejected with "pointer assignment target is incompatible", and no corpus case used one, so nothing noticed |
| D-098 | The leading whitespace of a spliced continuation line is skipped by asking again after each splice | a splice is removed where it stands, so a continuation line that begins with a space exposed that space as the start of a token. The result was "invalid input byte" at the first character of the continuation line, which is the shape every macro-heavy header in the world uses |
| D-099 | A comma that follows the last initializer in a braced list ends the list | the loop asked for another initializer after every comma, so the trailing comma that C allows and that most real code writes was parsed as the start of a further value. `int a[3] = {1, 2,};` was rejected, and so was every initializer list in the program being compiled |
| D-100 | An aggregate by value is split into eightbytes and each is named by what its bytes can hold, and the same rule answers for the caller and the callee | the compiler had no way to pass a struct or union by value at all, and the language document deferred it. The classification is derived from the layout the compiler already computes: a field of eight bytes or less that starts on an eightbyte boundary fills exactly that piece, and a piece holding any integer must travel in a general register because that register can carry a byte pattern a vector register cannot express. One routine answers for both sides, because a caller and a callee that disagree about a register are a silent wrong answer rather than a failure |
| D-101 | An expression of struct or union type has the address of the object as its value, and the IR instruction that carries it names the object type | an aggregate has no register wide enough to hold it, so the lowering already produced an address, but the instruction was typed as a pointer to the object. An argument that was an aggregate was therefore classified as a pointer, and a call that returned one had nowhere to put the result. A named type on the instruction is what lets the backend ask the ABI about the argument without consulting the syntax tree |
| D-102 | An eight- or sixteen-bit register operand is written with a REX prefix whenever an operand number is four or more | without a prefix those numbers name the legacy high byte and word registers, so a store of a `char` or `short` whose value happened to be in `RCX`, `RDX`, `RSI`, or `RDI` wrote the high byte of another register's full value. The defect predates the aggregate work and only became reachable when a narrow parameter slot made the high register numbers common |
| D-103 | A returned expression is converted to the type the function declares | `return` lowered the expression and gave it to the return without the conversion any other assignment performs, so a `float` expression returned from a `double` function reached the wider return register still in single precision. A program that added two floats and returned the sum computed `b + b`, because the value was read back from where the narrower form had been stored |
| D-104 | A compound assignment on a floating object widens both sides, combines them, and narrows the result | the compound-assignment encoder was written for integers only, so `x *= k` on a `float` loaded the stored bits, multiplied them as an integer, and stored the product. The defect predates the aggregate work and had no corpus case, because the corpus had no floating arithmetic |

| D-105 | A struct, union, or array that is the source of a copy is lowered as a value, not as an address, and a call that returns an aggregate gives its result the address of the space the lowering reserved for it | the copy of an aggregate took the address of its source expression, and the only things with an address are names, so assigning the result of a call to a variable was reported as an unsupported address expression. An aggregate of that type is a value whose value is an address, and the two were spelled the same way at the point where the difference mattered |
| D-106 | A conditional with two void branches has void type | the form a statement macro must be written in when the language has no statement expression is a conditional whose branches do nothing, and it was rejected as incompatible branches. A branch that is `void` and a branch that is a call returning `void` are the same type, so the rule that rejects the pair is the one that was wrong |
| D-107 | An aggregate of the memory class is written through a pointer the caller passes in the first general register, and the named arguments begin at the second | the first aggregate support carried a value in at most two registers and diagnosed anything larger, which left a large object unexpressible rather than merely unsupported. The pointer takes a register no named argument can have, so the two never compete; that is why the register that holds it does not have to be reserved in the layout of the argument list |
| D-108 | The address of an object survives a block move, because the move leaves the destination register one object past the last byte it wrote | the object copy is one instruction that advances both its source and its destination, and the address of the object was taken from the destination afterwards. A copy therefore named the end of the object rather than its start, which made every result of an assignment or a memory-class return one object too high, and the copy itself read from the wrong place |
| D-109 | A value of the 128-bit unsigned integer type is the address of the object that holds it, and the object's storage is two eightbytes in the frame | a value two registers wide has no register, so the lowering produces an address and the instruction is typed as the object type. This is the same shape an aggregate already had, so a wide value is classified, passed, and returned by the one rule rather than by a second one. The alternative — a pair of registers threaded through every instruction — would put a special case in every lowering decision rather than in one representation |
| D-110 | A conversion instruction onto or off the wide type records whether its operand is a wide value or a machine value | a conversion from a machine value needs storage of its own to leave the result in, and a conversion between two wide values changes nothing but the address. The two are spelled identically in the syntax tree, so the instruction says which it is; without that, a conversion between two wide values stored an address as though it were a number, and the low half of the value became the address of the object |
| D-111 | Every path of a wide shift leaves the low half in one register and the high half in the other, in that order, and the result is written out in that order | the paths were written separately and stored the halves in the order the arithmetic happened to produce them, so a shift of a whole eightbyte left the value in the half it came from. One order at the end of one block makes the paths interchangeable and makes the store the same for all of them |
| D-112 | A wide shift of no bits is the value itself, and a wide shift of the whole width leaves nothing | both cases were folded into one that produced zero, so `x << 0` produced zero. They are opposite answers to different questions — one is the identity and the other is the annihilation — and only the second is zero |
| D-113 | The immediate shift form writes its register through the extension bit, because the opcode's register field holds the operation and the shifted register is in the r/m field | the form emitted a fixed 64-bit prefix and put the register number in the low three bits, so any of the four registers above the seventh named the wrong one. The byte and word forms had already been given the prefix for the same reason; this form was written later and missed it. The defect predates the wide type and only became reachable when a shift began to use a high register |
| D-114 | A multiply of two wide values keeps the carry out of the low halves before the other three products overwrite it | the high half of the product is the sum of four half-products, and the one whose low half became the result's low half contributes a carry as well. That carry was added last from a register the three intermediate products had already overwritten, so a product that carried out of its low half lost exactly that bit. A hash function that multiplies two 64-bit values and takes the high half of the 128-bit product is the shape that reaches it |
| D-115 | A wide shift count is a constant, and a variable count is diagnosed | a machine shift count is six bits wide, so a wide shift by a variable amount cannot be one instruction. Rather than reduce the count silently, which computes a different answer, the case is refused with a diagnostic that names the reason |
| D-116 | A decimal exponent is applied one table entry at a time, with the significand carried in 128 bits and brought back to a word between entries | a single multiplication or division by one power of ten made the exponent's range the range of a table, so `1e30`, `1e300`, `1e-300` and the largest and smallest values the format can hold were all syntax errors. The steps need a normalisation between them, and the normalisation needs a sign convention: the value is a significand times two to the minus scale, so discarding low bits multiplies the retained part and the scale falls. The 53 bits the format keeps sit far above the 128 the working precision carries, so no bit that decides a rounding is ever discarded |
| D-117 | A constant below the format's range rounds to zero and is accepted; a constant above it is refused | zero is a value the format holds, so an underflowing constant has a value and refusing it would reject a legal literal. An overflowing one has no value, and that is the case where the text is nearly always a mistake, so it earns a diagnostic rather than a silent infinity |
| D-118 | A compound literal is an lvalue, and an array type written with no length is completed by the list that initializes it | a compound literal is an unnamed object, so the three operations that need an object rather than a value — taking its address, assigning through it, indexing it — were all refused. An array type with no length is the one type the initializer is allowed to complete, which is how a declared object of the same spelling works, so the list supplies the length and the type is judged afterwards |
| D-119 | A compound literal is a primary expression reached from the cast level, so the postfix loop takes the operand it is given | the literal was returned from the cast level without the operators that may follow a primary expression, so a member selection or an index applied to it selected from nothing. A second entry point to one loop is a smaller change than a special case inside the loop |
| D-120 | Each interface the target answers differently is declared in the shape a caller expects, and the header says in what respect the answer differs | a program written for a hosted system includes a header and calls a function. A header that omits the name does not compile; a header that declares it without saying what the target's answer is compiles and then misbehaves in a way that is hard to trace back to the interface. The declarations are the portable shape, and the difference is stated rather than left to be discovered |
| D-121 | What the target cannot do is reported as the target's limitation, with the value that names it, rather than approximated | the target has no directories, no window size, no line discipline, no monotonic clock, no signals, and no loader. Each of those has a plausible approximation — an empty directory, a fixed size, unchanged settings, a wall clock, a recorded handler, a null handle — and each approximation would be indistinguishable from a working one. A caller that checks the result sees why, and a caller that does not check gets a program that degrades rather than one that lies |
| D-122 | The version 1 startup contract hands `main` no environment, and `getenv` reports that no variable is set | the contract builds `argc` and `argv` from the process prefix and nothing else, and the target exposes no documented way for a running program to reach that prefix after startup. Reading the target's environment would need an interface revision that passes one, so until then `getenv` says what is true of this interface. A program that needs a variable finds none and takes its documented default, which is what a target with no environment for its programs means |
| D-123 | The console readiness, time of day, and date services are reached through thunks that fold the register layout each one leaves behind into a single value | the services answer in a register split the library would otherwise have to know: a pair of registers holding two fields each. A thunk that folds them keeps that layout in one place, next to the other services, instead of spreading it across the library. Console readiness needs it most: the service reports availability in the low byte and leaves the carry clear either way, so a value that looked like a count was a boolean |
| D-124 | The arithmetic routines are written from the numeric definitions of the functions they implement, and each states what it approximates and over what range | the target has no arithmetic service, so there is no library here to be consistent with. The exponentiation and the logarithm are the ones a program reaches for and the ones a short polynomial gets wrong silently, so both split the argument into a power of two and a small remainder and say so. A caller that needs more than the approximation can see the limit instead of discovering it |
| D-125 | A mapping is a block request with a bounded table of live mappings, and a release has to name the whole mapping | the target has one heap and no protection, so a mapping is a block. The table is bounded because a program that maps without unmapping would otherwise grow the image's own data without limit. A partial release is refused because it would leave the rest of a mapping reachable with no way to release it, which is worse than a refusal |
| D-126 | An image that includes the target library is linked in the load-biased form, and the raw form remains for a program with no data pointers | the library holds a table of pointers, so a data pointer in it cannot be resolved for an image loaded at an unknown bias. The raw form is a property of the program, not of the compiler, so a program that needs no data pointers still gets the smaller image |
| D-127 | A floating value is computed into a vector register, and every instruction that reads one reads a vector register too | the second operand of a binary operation, a comparison, and a compound assignment was moved out of a general register. A constant happens to leave its bits in the general register as well as the vector one, so a corpus built from constant operands passed and a program with a value in that position did not. Five further shapes had the same fault: a negation, a logical negation, an increment, a decrement, and the form an operator takes, which was decided by the type of its result rather than of its operand |
| D-128 | A conversion to the width a floating value already has performs no conversion | the conversion widened and narrowed regardless, and that is not a no-op: widening a single-precision value produces a double whose low half the narrowing keeps, so the pair is exact. It was not exact here, because a second widening in the chain read the double back as single precision and widened the wrong half. The shape is common, because a parser that wraps every operand in a conversion produces a chain |
| D-129 | The narrow form of the move that loads a vector register from a general register is not used; the wide form loads both widths | on this target the thirty-two-bit form of that move is decoded as a move to a multimedia register, so a sign mask loaded with it lands where the exclusive-or that needs it cannot see it, and a negation becomes a no-op. The wide form leaves the upper bits zero, which the exclusive-or of the low half does not care about, and it is one instruction either way |
| D-130 | A remainder is refused as zero when its quotient is too large to count, and a token list's reservation is bounded however large the estimate is | the target has no wider type to compute a remainder in and no way to do it a bit at a time while keeping the significand whole, so a quotient past the range of a 64-bit count has no remainder this implementation can produce. A reservation taken from a source's length is a good estimate and a poor request: a first-fit heap of a few mebibytes cannot promise one contiguous run of that size once the rest of a compilation is committed around it |
| D-131 | The target's resize service is not called from the target library | it exists, it is the obvious answer to a growing buffer, and a user process that calls it reboots the kernel. Measured, with a program that resizes a block twelve times: the first resize prints, the second reboots. A service that ends the process is not an interface to build on, and the cost of growing by copy is the price of a working allocator |
| D-132 | The target heap is extended to twelve mebibytes, on the target's `edit` branch, and CC64's contract states the new size | the compiler could not compile itself on the target. `src/backend/encoder.c` is the largest unit, and the target-built compiler reported `out of memory after requesting 8904693 bytes` from a heap of six mebibytes, while the host compiled the same unit in 23 ms and produced a byte-identical object — a shortfall of memory, not of correctness. The change is two facts that have to agree: the MCB chain must end where the identity map ends, and the page-directory helpers that index an entry must be bounded by the entry count rather than by a literal. Both bounds and the count are now derived from one definition in `include/mcb.inc`, because a chain bound copied into two files is how the literal `6*1024*1024` that bounded a process block was left behind when the heap was doubled. Measured with `tests/target_heap.c`: five mebibytes claimable on the pinned reference, eleven on the edit branch. Recorded as required by AGENTS.md §1 because CC64's self-hosting depends on it |
| D-133 | A command tail the target bounds cannot hold the whole argument list, so an argument of the form `@NAME` is replaced by the words inside `NAME` | the target's process contract gives a child 127 bytes at PSP+0xA1, 126 of them usable, measured with the target's own `ECHO` builtin. A link of the compiler names twenty-one objects, which is 126 characters including the options, so the tail was cut and the linker wrote its image to `S2.CO`. The compiler cannot fix a target's tail, and shortening the names would only move the bound: the program being compiled has thirty-eight units, so its link is 44 inputs. An argument list that has to fit in a fixed field is not an argument list, so the field and the list are separated. Nesting is bounded to eight files and a file to 65536 bytes, and a file that reaches either bound is refused rather than truncated, because a truncated list links the wrong image without saying so. A word may be quoted so a path may contain a space, and a bare `@` is an argument rather than a response file |
| D-134 | A harness reads the target's volume geometry out of the image instead of naming an address | the kernel slot was doubled to 512 sectors, which put the kernel extent at LBA 16..528 and so moved the volume from 512 to 1024 and the scratch block with it. Nine harnesses carried `--vol-lba 512` and the FAT12 tools carried `VOLUME_LBA = 512` as constants, so after the move they read and wrote sectors that were not the volume: an embedded program landed outside it, and the volume-cleanliness check reported on sectors the volume does not occupy. The address is a property of the target image, so it is read from the boot sector the target's own stamper wrote, identified by its OEM name and signature, and the kernel extent is read from the layout block that already single-sources it. A harness that named the address could only ever be right for the one revision it was written against; a harness that reads it follows whichever revision is checked out |
| D-135 | The kernel slot, the volume, and the scratch block move together, and the loader's staging buffer is placed to hold the slot | the slot is 512 sectors because the full selftest kernel no longer fits in 256, and the slot is where a target grows. Doubling it is not one line: the new extent has to clear the scratch block, so scratch moved into the band the move freed, and the volume moved past the kernel. The loader stages the whole kernel in real mode before the copy to 1 MiB, and its buffer sat at 0x70000, below the BIOS INT 13h stack at 0x90000 and the VGA window, which capped the slot at 256 sectors because nothing contiguous that long fits below them. It now sits at 0x10000, where 512 sectors reach 0x50000 and stay clear of the MBR, stage2, the BIOS stack, the VGA window, and the page tables built afterwards. Leaving the buffer where it was would have copied a quarter-mebibyte of scratch and volume into the kernel image, which is what five unrelated selftests reported when the slot was raised before the buffer was |
| D-136 | The runtime thunk that reads the target's date and time joins the two registers the service returns by moving one into place, not by shifting both | `AH=2Ah` leaves RCX=year and RDX=(month<<8)|day, and the value the thunk returns has those at bytes 2, 1 and 0. RDX already holds month and day in the order wanted, so the year is lifted two bytes above it; shifting instead returned the year shifted down and the month shifted up and dropped the day, so a program asking the target the time of day was told 2334-7-23. The time thunk had the same shape and the two were written identically, so fixing one alone would have left the pair disagreeing. Each half is taken 32 bits wide, because the service leaves the rest of the register to the caller and the bits above the fields are not the clock's — the shift form read those bits and returned them too. Found while reproducing D-137: the target's date was right and the compiler could not read it. `tests/target_rtc.py` fails with the old thunk and passes with the new one |
| D-137 | The target's date setter puts the day at 1 before writing the month | `rtc_set_date64` wrote year, then month, then day. The month write lands on whatever day the clock still holds, so moving to a month with fewer days than the current day names a date that never existed — the 29th of a 28-day month — and the clock then has to resolve it. Measured on the target with the clock holding the 29th: a request for 2001-02-28 was answered as 2001-03-28, the month carried forward and the day lost. That is the target's own test 68, and the reason it failed on the pinned reference too. Writing the day as 1 first makes every intermediate date real, because the 1st exists in every month, and the fields then land exactly as given. The target's suite goes from 88 passed and 1 failed with 6 skipped to 89 passed and none, and from 94 and 1 to 95 and none with the destructive tests running, on QEMU and on Bochs. Deliberately not reproduced by a CC64-side test: whether the clock's update tick lands between the guest's writes decides what an impossible date normalises to, so an external test of it would be testing the emulator's timing rather than either side |
| D-138 | A program's console input is the keyboard and the line together, and the status check holds the one character it had to take to find out | the target delivers console input on COM1, which is where its own shell reads it with `AH=03h`, and both emulators put a test's keystrokes there. The two services a user program uses to receive input, `AH=0Bh` and `AH=3Fh` on a console handle, consult only the PS/2 keyboard, so a child could never see the input the target actually delivers: a program that polled and then read got nothing and read end-of-file, and a 24,461-line editor could draw a screen and then never see a key. The fix uses the service the target already has rather than changing the target, because a service the shell depends on is not the thing to work around. The line cannot be asked whether a character is waiting without taking it, so the status check takes one and holds it for the read that follows; one is enough because a status check is always made for a read. The keyboard is asked first in both, because that answer costs nothing and because the target's shell also takes the keyboard before the line. `poll` and `read` go through the one accessor, so they cannot disagree about whether input is waiting |
| D-139 | A path that starts at the root names a file the same way the bare name does, and a path naming any other directory is refused | the target has one directory and the root is its name, so `/NOTES.TXT` and `NOTES.TXT` are the same file. A program that composes absolute paths, which is the portable way and is what the editor does because its own path handling requires a path to begin at the root, could open nothing: the leading separator went to the target's file services unchanged and was refused, which the target reported as the file not existing. This is not a limitation being papered over. There is no second directory, so the two names cannot differ, and the alternative of reducing a path to its last component would open a different file than the one asked for, which is worse than refusing. So a path with any other directory component is refused. Resolving the path is advancing a pointer, so nothing is copied |
| D-140 | The compiler's own library set lists the file calls, because the stream unit resolves a path through them | the set is chosen to keep the compiler image small, because the target's heap is small, so it listed the units the compiler called and nothing else. Resolving a path for a file call made the stream unit depend on the file unit, and an unresolved symbol is what said so — which is what the set is checked for. The file calls belong in it on their own account: the compiler opens files to read them. Putting the console's input accessor in the file unit rather than the terminal one keeps the dependency pointing one way, from the terminal down to the file, so the compiler image gains the file unit and not a terminal unit it never calls |

| D-141 | The buffer a `#` result is built in is sized by the same walk that writes it | the estimate counted one byte per character of the argument's tokens, while the writer emits two for every quote and backslash, and the closing quote and the terminator both had to come out of the same per-token allowance. So the result overran its buffer for any argument holding more than one token or any quote or backslash in it. Four of the 37 test units of the program CC64 compiles aborted the compiler with a heap corruption report, and the common shape was the `CHECK` macro, which takes one argument and stringizes it. The estimate and the writer are now one walk, so a fourth kind of token to escape cannot make them disagree again |
| D-142 | A directive ends at the end of its line, and the end of a line is the first token that begins one, as well as the newline when there is one | the directive's extent was found by scanning for a newline token. Where newline tokens are omitted there are none to find, so the scan ran to the end of the source and the first directive of a unit consumed the whole of it: every `#define` after the first was lost and everything after them was read as part of the last directive. The compiler's own line always keeps newlines, so this was reachable only through the library's option, which is a public field that the unit tests use and that names the behaviour. A token carries whether it begins a line whether or not newlines are kept, so that is now also the test, and only a real newline is stepped over afterwards: stepping one token past the end would drop the first token of the next line. Two tests were passing because of this rather than in spite of it, and both are now split into the half that must succeed and the half that must be diagnosed |
| D-143 | A preprocessing run that fails publishes no tokens at all | the run returned the tokens read before the failure, which are a prefix of a unit that was never translated. A caller that checks the return value does not read them, but a caller that reads the list first, or counts it, sees a truncated unit that is indistinguishable from a complete one. AGENTS.md §5 requires that a failed phase leave nothing that could be mistaken for a successful build, and the same applies a phase earlier: the list is emptied on failure. `tests/unit/test_frontend.c` states the invariant and had been passing only because the failure arrived before any token was read |
| D-144 | `-E` without `-o` writes to the standard output | the driver defaults the output path to `a.o` for every action, because compiling is the action that needs a name, and preprocessing inherited it: `cc64 -E unit.c` wrote the preprocessed text to a file called `a.o` in the working directory and printed nothing, and reported success. A mode whose whole output is its standard output has to write there. The name is still used when `-o` is given, and `-E -` keeps working. The check in `tests/run.py` looks for the default-named file as well as for the text, because the silent part of this was the file |
## Review rule

Every new non-obvious decision receives a row before implementation. A design
that requires studying unrelated source is rejected and redesigned from its
specification. `tests/audit.py` checks tracked source, forbidden artifact
patterns, provenance records, and clean milestone documentation. Release
review also records tool versions and performs a clean deterministic rebuild.
